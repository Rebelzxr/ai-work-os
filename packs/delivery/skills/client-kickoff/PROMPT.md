# Client kickoff — copy-paste edition

## What to give it

- The approved scope and the owner's record of acceptance.
- The due window, known source files and acceptance criteria.
- Only labelled, minimum-necessary project facts.
- Any constraints, correction limit or outside request already recorded.

## The prompt

```text
Prepare a client kickoff pack from the approved scope and supplied project facts.

Compare the scope with available inputs and mark each item ready, missing, unclear or outside scope. Write one consolidated request for all missing inputs, including why each is needed, an accepted format and the latest useful date. Create milestones with owner, dependency and check. Then write the first production brief with objective, audience or use case, deliverable shape, source list, constraints, acceptance criteria and correction limit.

Keep outside requests as change decisions. Do not invent approval, deadlines, files, access, brand rules or client facts. Do not treat the request as delivered. Begin with “Practice, not for use” for invented examples.
```

## What you get back

- A readiness table.
- One consolidated missing-input request.
- Milestones and dependencies.
- A first production brief and unresolved list.
- Owner decisions that remain open.

## Check before you use it

Check every missing input against the scope, remove unnecessary data requests, confirm that each milestone has a check, and verify that outside requests are not inside the deliverables. The owner checks the draft before any client contact.
