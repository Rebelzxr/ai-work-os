# WORKFLOW.md: how a job runs

`AGENTS.md` owns authority and safety. This is the loop for any non-trivial job.

## 1. Name the outcome and the owner
- One useful output, clear acceptance, stated assumptions.
- Read the nearest rules, the board row and the named source files. Fetch more only when needed.
- Check what already exists before researching outside.
- One accountable owner. One writer per file. Keep the finish line fixed.

## 2. Do the authorised work
- The request authorises reversible local work inside its scope. Do not bounce routine choices back to the human.
- For big jobs, give a short plan, then do it. Park new ideas in the backlog instead of widening scope.
- Delegate only for independent work or an independent review. Give each helper exact files, acceptance and a return format.

## 3. Check what matters
| Change | Check |
|---|---|
| Small, reversible edit | Read it back and run the focused check |
| Something a user touches | Run it the way the user would, including a failure case |
| Privacy, security, money, sends, deploys, shared data | The checks above plus an independent review of the real files |

## 4. Repair inside the limits
- Fix failed checks within the agreed scope, attempts and budget.
- After the same failure twice, name the missing decision or dependency and escalate with evidence. Keep doing other approved work.

## 5. Ask once, with everything ready
- Finish the work and the checks before asking for an external action.
- Show the exact version, the result, what is still unproven, your recommendation and the destination.

## 6. Save and close
- Record proof in the job receipt. Update the board only when the state or next action changed.
- Save the exact next action before a handoff or a stop.
- End with one STATUS line.
